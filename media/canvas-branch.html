Why it helps

A reviewer of a branch gets a diff, which answers one question: which lines moved. It cannot answer the three a reviewer has.

  • What was this change supposed to do?
  • Did it do that?
  • Did anything else move that nobody meant to move?

The intent is in the document and the fact is in the diff. coverage compares them. Its unmet list is a claim with no change behind it, and its unclaimed list is a change with no claim behind it. Neither list can come out of a diff tool, which holds one of the two sets.

Where the code runs

done
Worth: a document that cannot hang or end Leela

A canvas executed its Python in the web process. One while True: hung every request Leela served. One os._exit() ended Leela. This is the change that matters most in the branch.

leela/blocks/canvas/context.pyleela/blocks/canvas/live.pyleela/blocks/canvas/store.py
pkg:kundapkg:ramabana

Kunda's execute(timeout=) does not return on a busy loop, so the caller cannot wait on it alone. This waits, interrupts, waits again, then replaces the kernel and says the namespace is gone. A document that will not stop costs its own names and nothing else.

One base holds what does not care where code runs. Runtime is this process's, for the spike and the tests. KernelRuntime is a kernel. Nothing in either reaches into a namespace dict.

The trust line gates what evaluates, not what edits. A markdown file from anywhere can be opened, read and written. Its code waits for one deliberate click. A first attempt gated inserting an empty code brick, which made a document unwritable.

The change and the page

doing
Worth: all of the review step

A bundle claims a region, names a goal and owns a list of files. This is the half that compares the claim with the diff, and the half that writes the comparison out.

leela/blocks/canvas/change.pyleela/blocks/canvas/lit.cssleela/blocks/canvas/lit.pyleela/blocks/canvas/triage.difftools/make_change_page.py
pkg:mdhtmlpkg:gheasy

matched is a claim the diff confirms. unmet is a claim with nothing behind it. unclaimed is a file that moved with no claim on it. A claim is a glob or a name, so a bundle can own a folder.

One change as a document. For each file it emits the hunks, then every brick citing that path. A citation is a name or a glob: a note on docs/screenshots/* heads the run of fifteen it describes instead of repeating under each. A file id is its basename, or its whole path when two files share one basename.

The renderer writes no script, so the page works with JavaScript off. DIFF_CAP ends a long hunk in a count and DIFF_COLS ends a long line in one. A generated artifact had otherwise put 12,650 lines and three megabytes into a page nobody could read.

What running it found

done
Worth: a suite that finishes

The kernel killed pytest -m slow a third of the way in and it reported nothing. Fixing that turned up three more faults, none of them in the canvas.

README.mddocs/*.mdmedia/*.htmlmedia/*.mdtests/*tests/blocks/*tests/fixtures/*
pkg:kundapkg:shalya

The harness built a model engine per browser workspace. No engine sat at 290MB, the first took it to 871MB and the second to 3.1GB. Each streaming test then added two to three gigabytes while the Python heap stayed flat, which puts the growth inside the engines. A browser test drives painting and panels and needs no model. Every workspace gets the scripted backend: 80 tests, 4m29s, 967MB.

TurnRunner._reap read Thread.is_alive alone. That is False before a thread starts, and False after it ends. start publishes the pending turn and only then starts its worker. A request arriving in that window reaped a live turn. The fix reads ident first.

Five monkeypatches aimed at Leela's re-exports, not at the name the library reads. kunda.pool imports Kernel under its own roof and _class_for reads it there. The pool ignored the fakes. One test failed and one hung on a real kernel that never signalled.

One test resolved nbdev-prepare off the ambient PATH. It therefore passed or failed on how somebody invoked pytest. A sibling test owns the question of whether the environment carries nbdev. This one states that precondition and checks that the resolved script is what runs.
