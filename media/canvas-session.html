Why it helps

A reviewer of a change gets a diff. A diff answers one question: which lines moved. It cannot answer the three questions a reviewer actually has.

  1. What was this change supposed to do?
  2. Did it do that?
  3. Did anything else move that nobody meant to move?

The diff cannot answer them because the diff does not know the intent. Only the document knows. So the document states the intent, the diff states the fact, and Leela compares them. The comparison is coverage. Its unmet list is a claim with no change behind it. Its unclaimed list is a change with no claim behind it. No diff tool can produce either list.

This page shows that comparison at the top, as chips, before any code.

Why can a diff tool not report unclaimed on its own?

Because unclaimed is the difference between two sets, and a diff tool holds only one of them. It holds the files that moved. It does not hold the files a change said it would touch. That set is written in the document, in each bundle's paths. Subtract one from the other and you have a finding. Hold only one and you have a file list.

A question names its own scope, its pins and its budget. resolve returns the exact bricks, each with the reason it was chosen. render emits the cells that ramabana's compact_notebook_context already knows how to shed.

A notebook decides what the model reads by position: every cell above the question. That is right for a script and wrong for a plan, because a plan holds four lines of work at once. One case shows it. An audit belongs to the question at the top of the page and to the question at the bottom, and to nothing between them. Position cannot say that. A pin can.

A question states its own rule, and the rule is four fields. scope gathers the first set, pins add what the scope missed, and mutes remove what it caught. An unknown scope becomes page rather than an error, so a typed attribute cannot stop a document from opening.

The budget sheds the least useful brick first, not the oldest. A brick a question pinned survives the budget, and so does the goal. This is why resolve returns Items with a why on each one: a reviewer can see what was dropped and ask why.

The state of a change is derived. A bundle whose tasks are all done, and whose files all moved, is done. Nothing writes that word into the file.

state reads the word off the document. One blocked task blocks the change. Every task done, and every claimed file moved, makes it done. A change with no diff behind it is not punished for that, because files_ok treats an absent diff as no evidence, not as evidence against.

The comparison a diff tool cannot make:

coverage is the comparison. matched is a claim the diff confirms, unmet is a claim with nothing behind it, and unclaimed is a file that moved with no claim on it. The third list is the one no diff tool can produce, because only the document holds the promise to subtract from.

The page

Leela now assembles this page. The tool that used to do it picks a file and prints a line.

page is the whole assembly, and it is Leela's, not a script's. It fills the slots, counts the files, and writes the HTML in one call. It returns the file list and the unclaimed list, so a caller sees the finding without reading the page.

A diff brick with no body is a slot. It says which paths it wants and which two commits to compare. place_diff calls git once per slot and replaces the slot with one brick a file. A brick no bundle claims is marked, and the page shows a warning on it.

place_diff reads the request off the brick. A diff brick with a body is content, and is left alone, so a pasted diff is never overwritten. Each slot becomes one brick a file, and a file no bundle claims gets claimed=no, which the page shows as a warning.

The page folds anything longer than a phone screen, and a diff body scrolls sideways inside its own box, so a long line never widens the page.

The renderer folds a diff longer than a phone screen, and the summary still names the file and the counts. It drops the git headers a reader does not need. It writes no script, so the fold is <details> and the page works with JavaScript turned off.

The library

done
Worth: the palette, with no second process

The palette used to be an HTTP call to a second server. It is now an entry-point group. A library answers four questions: its manifest, one brick, that brick's wiring, and its own routes. An HTTP host answers the same four, and stays for a library that is not installed.

docs/bricks.mdextensions/bricks/*leela/blocks/canvas/bricks.pytests/fixtures/*
pkg:leela-bricksdoc:docs/bricks.md

The four questions are the whole contract. A library that answers them needs to know nothing about Leela, and Leela needs to know nothing about the library.

A library answers four questions and knows nothing about Leela. manifest lists its components, find returns one, wire returns the code that fills its ports, and mount puts its own routes on the app it is handed. manifest is read in process, so the palette needs no second server.

needs is read off the wiring's own imports, so a component cannot claim a dependency it does not have, and cannot hide one it does.

needs reads the imports out of the wiring text. A component cannot claim a dependency its code does not import, and cannot hide one it does. The standard library is dropped, so the list is what a person must install before the cell will run.

A library never writes its own name into a src string. LIB comes from __name__, so renaming the package renames every src it serves. This is what made extensions/bricks extract with no code change: eight files moved, and the only edit was to bricks.py, which grew a Registry.

The wiring

CAPS must name exactly what the routes read off ctx. The canvas block reads two things: the file system, and the model.

CAPS is a promise about ctx, and Leela checks it. A route that reads a capability the block did not declare fails at load, not at request time. This is why the canvas block asks for two things and no more.
