Why it helps

A reviewer of a change gets a diff, which answers one question: which lines moved. It cannot answer the three a reviewer has.

  1. What was this change supposed to do?
  2. Did it do that?
  3. Did anything else move that nobody meant to move?

The intent is in the document, not in the diff. So the document states the intent, the diff states the fact, and coverage compares them. Its unmet list is a claim with no change behind it, and its unclaimed list is a change with no claim behind it. Neither list can come out of a diff tool, which holds one of the two sets.

This page shows that comparison at the top, as chips, before any code.

Why can a diff tool not report unclaimed on its own?

unclaimed is the difference between two sets. A diff tool holds the files that moved, and not the files a change said it would touch, which are in each bundle's paths. With one set you have a file list, and with both you have a finding.

Worth: the file every other part reads

A canvas is a markdown file. Prose stays prose. A brick is a fence or a comment wrap, so every markdown reader shows the file and git shows a useful diff. The ast module reads the dataflow between code bricks off the code itself.

Two brick shapes, and the shape follows the content. Code goes in a fence, because a fence is how markdown holds code. A goal or a task goes in a comment wrap, because a reader should see the words and not the markup.

A fence holds what markdown already knows how to show, so a code cell stays a code block. A comment wrap holds what a reader should read as prose, so a goal shows its words and not its markup. KINDS is the whole vocabulary, and a document with a word outside it does not parse.

The graph is a read, not a record. defs_of asks the code what it defines and reads_of asks what it reads. Two bricks are joined when one defines what the other reads.

order reads the dependency from the code. _owners says which brick defines each name, and b.reads says which names a brick needs, so no person draws an edge. On a cycle the visit stops and the document order stands, so a plan with a loop in it still opens.

A question names its own scope, its pins and its budget. resolve returns the exact bricks, each with the reason it was chosen. render emits the cells that ramabana's compact_notebook_context already knows how to shed.

A notebook sends every brick above the question. A pin sends the two that matter, wherever they sit. An audit belongs to the question at the top of the page and the one at the bottom, and to nothing between.

A question states its own rule, and the rule is four fields. scope gathers the first set, pins add what the scope missed, and mutes remove what it caught. An unknown scope becomes page rather than an error, so a typed attribute cannot stop a document from opening.

The budget sheds the least useful brick first, not the oldest, and never a pin or the goal. Each Item carries the why that put it there, so a reviewer can see what was dropped.

The state of a change is derived. A bundle whose tasks are all done, and whose files all moved, is done. Nothing writes that word into the file.

state reads the word off the document. One blocked task blocks the change, and every task done with every claimed file moved makes it done. files_ok treats an absent diff as no evidence, so a change nobody has diffed yet does not read as work not started.

The comparison a diff tool cannot make:

matched is a claim the diff confirms, unmet is a claim with nothing behind it, and unclaimed is a file that moved with no claim on it. A claim is a glob, so leela/blocks/canvas/* covers every file the change touched in that folder without naming one of them.

The page

Leela now assembles this page. The tool that used to do it picks a file and prints a line.

page fills the slots, counts the files and writes the HTML in one call. It returns the file list and the unclaimed list, so a caller sees the finding without opening the page.

A diff brick with no body is a slot. It says which paths it wants and which two commits to compare. place_diff calls git once per slot and replaces the slot with one brick a file. A brick no bundle claims is marked, and the page shows a warning on it.

place_diff reads the request off the brick. A diff brick with a body is content, and is left alone, so a pasted diff is never overwritten. Each slot becomes one brick a file, and a file no bundle claims gets claimed=no, which the page shows as a warning.

The page folds anything longer than a phone screen. A diff body scrolls sideways inside its own box, so a long line never widens the page.

The renderer folds a diff longer than a phone screen, and the summary still names the file and the counts. It drops the git headers a reader does not need. It writes no script, so the fold is <details> and the page works with JavaScript turned off.

The library

done
Worth: the palette, with no second process

The palette used to be an HTTP call to a second server. It is now an entry-point group. A library answers four questions: its manifest, one brick, that brick's wiring, and its own routes. An HTTP host answers the same four, and stays for a library that is not installed.

docs/bricks.mdextensions/bricks/*leela/blocks/canvas/bricks.pytests/fixtures/*
pkg:leela-bricksdoc:docs/bricks.md

The four questions are the whole contract. A library that answers them needs to know nothing about Leela, and Leela needs to know nothing about the library.

A library answers four questions and knows nothing about Leela. manifest lists its components, find returns one, wire returns the code that fills its ports, and mount puts its own routes on the app it is handed. manifest is read in process, so the palette needs no second server.

needs is read off the wiring's own imports, so a component cannot claim a dependency it does not have, and cannot hide one it does.

needs reads the imports out of the wiring text. A component cannot claim a dependency its code does not import, and cannot hide one it does. The standard library is dropped, so the list is what a person must install before the cell will run.

A library never writes its own name into a src string. LIB comes from __name__, so renaming the package renames every src it serves. This is what made extensions/bricks extract with no code change: eight files moved, and the only edit was to bricks.py, which grew a Registry.

The wiring

CAPS must name exactly what the routes read off ctx. The canvas block reads two things: the file system, and the model.

CAPS is a promise about ctx, and Leela checks it. A route that reads a capability the block did not declare fails at load, not at the request that reads it.

What running it found

Running the merged block end to end found two faults that reading it could not.

Typing in a code brick was lost. An insert anywhere in the document runs cvSync, which keeps the element and hands it a new brick object. The textarea then wrote to an object the document no longer held, and the next flush read the older body. cvEdit writes through to cvBrick(id), and cvKeepEdits carries an edited body across the sync. The browser test in tests/test_web_slow.py returns the empty body on the code before the fix.

The context basket has a route and no panel. /canvas/context returns the exact bricks one question will send, each with the rule that chose it, and 51 tests cover the model. The merged editor has no control that opens it, because neither branch built one: the canvas branch built the editor and this side built the basket. It is t14 above.
